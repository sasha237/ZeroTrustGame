# Accessibility — code-level pass (M4, WCAG 2.1 AA target)

This document records what was verified at the code level and what remains owed
(a full assistive-technology/Lighthouse run requires a Chrome-capable machine — see "Owed").

## Verified in code

- **Keyboard operability**: all interactive controls are native elements (`<button>`,
  `<input type="range">`, form fields) — steppers, submit, draw toggle, replay scrubber,
  mode/auth/lobby/observer/reset screens are reachable and operable by keyboard in the
  order they appear in the DOM. No `tabindex` traps; the app has no mouse-only gestures.
- **Visible focus**: `:focus-visible` gives a high-contrast `#79b8ff` outline on the dark
  theme (contrast > 4.5:1 against all surfaces); `:focus:not(:focus-visible)` is cleared
  so pointer users don't get noise.
- **Modals**: `HelpModal` has `role="dialog"`, `aria-modal="true"`, an initial-focus
  move to the first focusable element, a Tab/Shift-Tab **focus trap**, **Escape** to
  close, and **focus return** to the invoking element on unmount. Backdrop click also closes.
- **SVG graph**: the root `<svg>` is `role="group"` with an app-level label; every policy
  node group carries a `<title>` with policy name, side, current level and pending
  direction; every indicator bubble carries a `<title>` (name + value). Decorative
  layers (edges, cluster backgrounds) are `aria-hidden="true"`.
  - **Design choice**: we deliberately did NOT use `role="img"` on the graph, because
    that hides all child content from assistive tech — per-node names would be lost.
    The equivalent accessible alternative for the full per-level effect data is the
    **policy tables in HelpModal** (`?` button), which are real HTML tables with
    header cells, keyboard-scrollable and screen-reader friendly.
- **Live regions**: the events feed (`Rail`) is `aria-live="polite"` so turn resolutions
  and reconnect banners are announced without stealing focus.
- **Icon-only buttons**: every graphical button (`?` help, `✕` dismiss in error/replay
  banners, policy-card close, replay prev/next) has an `aria-label` (localized EN/RU).
- **Forms**: every input has a wrapping `<label>`; errors use `role="alert"`
  (auth/reset/lobby screens).
- **Reduced motion**: a `prefers-reduced-motion: reduce` media query zeroes
  animation/transition durations globally (covers the reveal/summary transitions).
- **Color contrast** (computed against the dark theme):
  - `--text #e6edf3` on `--bg #0b0f14` ≈ 15.4:1; on `--panel #131a22` ≈ 14.4:1.
  - `--muted #8b98a5` on `--bg` ≈ 6.3:1; on `--panel` ≈ 5.9:1; on `--panel-2 #18222d` ≈ 5.4:1 — all ≥ 4.5:1.
  - Status colors are always paired with text/icons, never color alone (danger gauges
    also show counter text like "grace"/"3/3"; feed items carry ▲/▼ glyphs).

## Owed (needs a browser + AT)

- Lighthouse / axe scan on a Chrome-capable machine (not available on the build box).
- Screen-reader walkthrough (NVDA/JAWS on Windows, VoiceOver on macOS) of: a full
  planning → submit → reveal → game-over loop, observer replay scrubbing, and the
  reset-password flow.
- Focus-order audit with real keyboard traversal across all four screens (code order
  matches visual order everywhere we render, but a human pass is owed).
- Motion audit: confirm the reveal transition honors the reduced-motion query in a
  browser with forced reduced motion enabled.
